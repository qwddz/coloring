# Чек-лист: от кода до закрытого тестирования

Порядок шагов до закрытого тестирования в Google Play (личный аккаунт: 12+ тестировщиков, 14 дней подряд). **Все шаги вне репозитория (ключи, Play Console, сайт, тестировщики) выполняет пользователь.** Агент готовит тексты (`play_console.md`, `listing.md`, `site/colors/*.html`) и проверяет сборку. Факты, которые зависят от итоговой сборки, помечены **проверить после WP9**; спорные решения помечены **проверить**.

Условные обозначения: `[агент]` сделано или проверяется агентом, `[пользователь]` делает только пользователь.

## 0. Перед началом

1. `[агент]` `flutter analyze` без замечаний, `flutter test` зелёный, `dart format --set-exit-if-changed lib test`.
2. `[агент]` Пробная релизная сборка с фиктивными define и отладочной подписью (Gradle предупредит) проходит; записан размер AAB и список разрешений слитого манифеста: `INTERNET`, `ACCESS_NETWORK_STATE`, `BILLING`, `WRITE_EXTERNAL_STORAGE` (≤ 29, `maxSdkVersion="29"`, с `requestLegacyExternalStorage` в приложении), `DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION`; нет `AD_ID` и `READ_MEDIA_*`. **Проверено в WP9** (2026-11-18, minSdk 24)
3. `[пользователь]` Решить открытые вопросы: категория и возрастные группы (**проверить**, см. `play_console.md`), цена `full_version` (по умолчанию US$4.99), адрес CDN.
4. `[пользователь]` Заменить временную иконку (`assets/icon/`, см. «Commands» в `CLAUDE.md`) и подготовить feature graphic 1024 × 500 и скриншоты (список в `listing.md`).

## 1. Ключ загрузки (keystore)

`[пользователь]` Создать один раз, хранить вне репозитория и сделать резервную копию (потеря ключа загрузки решается обращением в поддержку Play, но лучше не терять):

```bash
mkdir -p ~/keys/coloring
"/Applications/Android Studio.app/Contents/jbr/Contents/Home/bin/keytool" -genkey -v -keystore ~/keys/coloring/upload.jks -keyalg RSA -keysize 2048 -validity 10000 -alias upload
```

Затем записать `~/keys/coloring/key.properties`:

```
storeFile=/Users/<you>/keys/coloring/upload.jks
storePassword=…
keyAlias=upload
keyPassword=…
```

Ни `.jks`, ни `key.properties`, ни `.env` не коммитить (они в `.gitignore`).

## 3. Релизная сборка

1. `[пользователь]` Подготовить `.env` с `REVENUECAT_GOOGLE_API_KEY` (ключ `goog_…` проекта RevenueCat для приложения `app.animosaic.coloring`) и `REVIEW_CODE`. Решить `CDN_BASE_URL` для закрытого теста (если все картинки пока бесплатные и лежат в приложении, CDN всё равно должен быть задан: сборка без него остановится на старте).
2. `[пользователь]` Собрать подписанный AAB (команда из «Release build» в `CLAUDE.md`):

```bash
COLORING_KEY_PROPERTIES=~/keys/coloring/key.properties flutter build appbundle --release \
  --build-number=$(date -u +%y%m%d%H) \
  --obfuscate --split-debug-info=build/symbols \
  --dart-define=CDN_BASE_URL=<cdn url> \
  --dart-define=REVENUECAT_API_KEY=$(grep '^REVENUECAT_GOOGLE_API_KEY=' .env | cut -d= -f2-) \
  --dart-define=REVIEW_CODE_SHA256=$(grep '^REVIEW_CODE=' .env | cut -d= -f2- | tr -cd 'A-Z0-9' | shasum -a 256 | cut -c1-64)
```

3. AAB лежит в `build/app/outputs/bundle/release/app-release.aab`. Размер: 61,9 МБ (61 918 087 байт), замер WP9 с `--obfuscate`, debug-подпись, 2026-11-18; финальный размер зависит от картинок в `assets`.
4. `[пользователь]` **Сразу сохранить `build/symbols`** этой сборки (например в `~/keys/coloring/symbols/<build-number>/`): `flutter clean` её удаляет, а без неё трассы обфусцированной сборки не прочитать. Декодирование: `flutter symbolize -i <trace.txt> -d build/symbols/app.android-arm64.symbols`.
5. `[пользователь]` `versionCode` должен расти с каждой загрузкой: `--build-number` от даты и часа UTC это обеспечивает; две загрузки в один час требуют ручной правки номера.
6. Если Play ругнётся на `WRITE_EXTERNAL_STORAGE`, прочитать предупреждение: разрешение объявлено только до API 29 (`maxSdkVersion`). В слитом релизном манифесте так и есть (WP9).

## 7. Внутреннее тестирование (internal testing), первым

`[пользователь]`:

1. Testing → Internal testing → Create release → загрузить AAB. Список тестировщиков: свой e-mail (аккаунт Google на устройстве).
2. Установить по ссылке-приглашению на живом телефоне. Пройти путь: категория → картинка → выбор режима → раскраска → «Мои работы» → продолжить; «Сохранить в галерею»; «Поделиться» (родительская проверка → системное окно).
3. Включить на устройстве старый Android (7–10), если он есть: при сохранении в галерею должен появиться системный запрос на доступ к хранилищу. **проверить**
4. Проверить ссылки политики и условий в приложении (настройки, «О приложении», экран «Полная версия»).

## 8. Продукт `full_version` и покупка

`[пользователь]`, **только после первой загрузки AAB** с окончательным package name:

1. (Создан 2026-11-23 как черновик: способ покупки `buy` с обратной совместимостью, US$4.99 и пересчёт на 174 страны, в Украине 269.99 UAH; названия и описания en/uk/ru.) Monetize → In-app products → создать `full_version` (one-time, non-consumable), название и описание на en/uk/ru, цена (по умолчанию US$4.99), пересчёт по странам, затем просмотреть UAH и EUR вручную.

3. В RevenueCat (проект `proj94119f87`) продукт `full_version` уже создан и привязан к entitlement `full` и пакету `$rc_lifetime` оффера `default` (2026-11-23, через API v2). ## 9. Закрытое тестирование (closed testing) и 14 дней

`[пользователь]`:

1. Testing → Closed testing → Create track (или использовать Alpha) → выпуск с тем же AAB (можно «Add from library», если он уже загружен в internal). Страны: выбрать (страны с оплатой, **проверить**).
2. Список тестировщиков: Google Group (удобно: люди вступают сами и вы не вносите адреса вручную) или e-mail-список. Нужно **минимум 12 человек**, лучше 15–25 (часть отвалится). Они должны быть **подписаны (opted-in) на тест** по ссылке приглашения; одного добавления в список мало.
3. Разослать ссылку для opt-in и попросить установить приложение из Play и не удалять его все 14 дней.
4. Отправить выпуск на проверку. Первая проверка бывает до нескольких дней.
5. **Часы 14 дней** идут с момента, когда 12+ тестировщиков подписаны на закрытый тест; требование: 12+ подписанных тестировщиков **14 дней подряд**. Дату старта записать (это дата, когда число подписанных впервые достигло 12). Если число упало ниже 12, ждать и добирать людей. **проверить** текущие условия в Play Console (раздел «Production access»), правила Google менялись.
6. На 14-й день в консоли подать заявку на доступ к production (Apply for production), ответить на вопросы о тесте (что проверяли, какие замечания исправили).
7. Во время теста новые сборки загружать с большим `versionCode` и сохранять новые `build/symbols`; тестировщики получают обновления автоматически, часы не сбрасываются.
